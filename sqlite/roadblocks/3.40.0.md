# SQLite 3.40.0 Roadblocks

**Release Date:** 2022-11-16

## Changes
- **WASM (WebAssembly) build support** - Official WASM distribution
- **Recovery extension** - New extension for database recovery
- **sqlite3_filename typedef** - New type for file handling
- **sqlite3_value_encoding() API** - Query value encoding
- **PRNG change: RC4 → Chacha20** - More secure random number generation
- Query planner improvements for partial indexes
- Enhanced support for RETURNING clause
- Performance improvements for UPDATE and DELETE

## Potential Roadblocks
| Change | Risk | Impact |
|--------|------|--------|
| **PRNG change (RC4 → Chacha20)** | **High** | **random.c, sqliteInt.h**: Complete replacement of PRNG algorithm. May conflict with Comdb2's random number usage or custom PRNG implementation. Could affect: test reproducibility, RANDOM() function, internal algorithms using randomness. |
| **sqlite3_filename typedef** | **Medium** | **sqliteInt.h**: New typedef for file handling. May conflict with Comdb2's VFS layer or file handling code. |
| **sqlite3_value_encoding() API** | **Low** | **vdbe.c, vdbeapi.c**: New API for querying value encoding. Low risk unless Comdb2 has custom encoding handling. |
| **Recovery extension** | **Low** | New extension (optional). No impact unless explicitly enabled. |
| **WASM support** | **Low** | Build-time feature. No runtime impact on Comdb2. |
| **Partial index query planner** | **Medium** | **where.c**: Enhanced optimization for partial indexes. Could interact with Comdb2's index selection logic. |
| **RETURNING clause enhancements** | **Low** | **insert.c, update.c, delete.c**: Enhanced RETURNING support. Low risk unless Comdb2 modifies RETURNING. |

## Action Items
1. **HIGH PRIORITY**: Review PRNG changes
   - Audit random.c for Chacha20 implementation
   - Check if Comdb2 has custom PRNG or depends on RC4
   - Verify RANDOM() function behavior
   - Update tests that depend on specific random sequences
   - Check if any algorithms depend on RC4 characteristics

2. **MEDIUM PRIORITY**: Review file handling changes
   - Check sqlite3_filename typedef usage in sqliteInt.h
   - Verify compatibility with Comdb2's VFS layer
   - Test file operations still work correctly

3. **MEDIUM PRIORITY**: Test partial index optimization
   - Review where.c changes for partial indexes
   - Verify Comdb2's index selection logic still works
   - Test queries using partial indexes

4. **LOW PRIORITY**: Review new APIs
   - Check sqlite3_value_encoding() implementation
   - Verify no conflicts with Comdb2's value handling
   - Consider if new APIs are useful for Comdb2

5. **Testing**:
