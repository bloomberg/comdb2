# SQLite 3.31.0 Roadblocks

**Release Date:** 2020-01-22

## Changes
- Generated columns (both STORED and VIRTUAL)
- Added SQLITE_DBCONFIG_TRUSTED_SCHEMA option
- Improvements to ALTER TABLE
- Enhanced query planner with better index selection
- Performance improvements in the byte-code generator

## Potential Roadblocks

| Change | Risk | Impact |
|--------|------|--------|
| Generated columns (STORED/VIRTUAL) | **Critical** | Affects **parse.y**, **build.c**, **insert.c**, **select.c**, **alter.c**. Comdb2 has its own schema management and constraints system. STORED columns impact storage layer and replication. VIRTUAL columns affect query execution. Major integration effort required. |
| ALTER TABLE enhancements | **High** | Changes to **alter.c**, **build.c**. May conflict with Comdb2's schema change mechanism and DDL handling. |
| SQLITE_DBCONFIG_TRUSTED_SCHEMA | **Medium** | Security feature in **sqliteInt.h**, **main.c**. Need to evaluate impact on Comdb2's security model and ensure proper initialization. |
| Query planner index selection | **Medium** | Modifications to **where.c**, **whereInt.h**. Could affect Comdb2's custom index hints and query optimization. |
| Byte-code generator changes | **Medium** | Updates to **insert.c**, **delete.c**, **update.c** for generated columns. May conflict with Comdb2's distributed execution model. |

## Action Items

1. **Generated Columns Analysis** (Critical Priority)
   - Deep dive into parse.y grammar for generated column syntax
   - Review build.c changes for table creation with generated columns
   - Analyze insert.c modifications for STORED column computation
   - Assess select.c changes for VIRTUAL column evaluation
   - Determine if Comdb2 schema (.csc2 files) should support this feature
   - Plan integration with Comdb2's constraint system

2. **Storage Layer Impact**
   - Evaluate how STORED columns affect row format and indexes
   - Review implications for Comdb2's replication and recovery
   - Test generated columns with Comdb2's compression and inline blob handling
   - Verify compatibility with ondisk schema versioning

3. **ALTER TABLE Integration**
   - Review ALTER TABLE changes for adding/modifying generated columns
   - Test compatibility with Comdb2's schema change transactions
   - Ensure live schema change (SC) works with generated columns

4. **VDBE and Execution**
   - Identify new opcodes for generated column evaluation
   - Test VIRTUAL column computation in remote queries
   - Verify triggers and generated columns interaction

5. **Security Configuration**
   - Review SQLITE_DBCONFIG_TRUSTED_SCHEMA implementation
   - Integrate with Comdb2's authentication and authorization
   - Test with Comdb2's stored procedures and Lua functions

6. **Query Planner Testing**
   - Test index selection with generated columns
   - Verify query plans remain optimal with Comdb2's modifications
   - Benchmark performance impact
