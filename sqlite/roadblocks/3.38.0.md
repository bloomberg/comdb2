# SQLite 3.38.0 Roadblocks

**Release Date:** 2022-02-22

## Changes
- JSON -> and ->> operators for JSON extraction
- JSON functions built-in by default (no longer optional)
- New unixepoch() function
- sqlite3_error_offset() API
- Bloom filter optimization in query planner for large UNION queries
- Query planner improvements for OR-connected terms
- Enhanced VACUUM INTO with conditional syntax

## Potential Roadblocks
| Change | Risk | Impact |
|--------|------|--------|
| **JSON operators (-> and ->>)** | **High** | **parse.y**: New operators require parser changes. Comdb2's custom parser modifications may conflict with operator precedence and parsing rules. |
| **JSON built-in by default** | **Medium** | **func.c**: JSON functions now compiled in by default. May conflict with Comdb2's function registry or custom JSON handling if present. |
| **Bloom filter in query planner** | **Critical** | **where.c, whereInt.h**: New Bloom filter optimization for multi-way joins and large UNION queries. This is a significant query planner change that could conflict with Comdb2's custom query optimization strategies. |
| **unixepoch() function** | **Low** | **func.c**: New date/time function. Minimal impact unless Comdb2 has custom date handling. |
| **sqlite3_error_offset() API** | **Medium** | **sqliteInt.h, parse.y**: New error reporting mechanism. Requires tracking token positions during parsing. May conflict with Comdb2's error handling. |
| **Query planner OR optimization** | **High** | **where.c, whereInt.h**: Enhanced optimization for OR-connected WHERE clauses. Could interact poorly with Comdb2's query rewriting. |
| **VACUUM INTO enhancements** | **Low** | **build.c**: Minor syntax additions. Low risk unless Comdb2 heavily modifies VACUUM. |
