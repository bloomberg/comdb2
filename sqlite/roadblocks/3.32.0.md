# SQLite 3.32.0 Roadblocks

**Release Date:** 2020-05-22

## Changes
- Approximate ANALYZE using PRAGMA analysis_limit
- Query planner improvements for joins and subqueries
- Added support for the MATERIALIZED and NOT MATERIALIZED hints on CTEs
- Performance optimizations in the code generator
- Enhanced constant propagation in WHERE clause
- Improved handling of ORDER BY in compound SELECT statements

## Potential Roadblocks

| Change | Risk | Impact |
|--------|------|--------|
| Approximate ANALYZE | **High** | Affects **analyze.c**. Comdb2 has its own statistics collection (analyze/stat4). Integration requires careful review to ensure Comdb2's distributed statistics remain accurate and aren't degraded by approximation. |
| MATERIALIZED/NOT MATERIALIZED CTE hints | **Medium** | Changes to **parse.y**, **select.c**. May interact with Comdb2's query optimization decisions for remote vs. local execution. |
| Query planner join improvements | **Medium** | Modifications to **where.c**, **whereInt.h**. Could affect Comdb2's join strategies and distributed query planning. |
| WHERE clause constant propagation | **Medium** | Changes in **where.c**, **expr.c**. May interact with Comdb2's custom expression handling and remote predicate pushdown. |
| ORDER BY in compound SELECT | **Low** | Updates to **select.c**. Should be mostly compatible but needs testing with Comdb2's distributed queries. |

## Action Items

1. **Analyze.c Integration**
   - Review PRAGMA analysis_limit implementation
   - Assess impact on Comdb2's distributed statistics collection
   - Determine if approximate ANALYZE is appropriate for distributed database
   - Test with Comdb2's ANALYZE TABLE command
   - Verify stat4 compatibility

2. **CTE Materialization**
   - Review parse.y changes for MATERIALIZED/NOT MATERIALIZED hints
   - Test CTE execution with Comdb2's query engine
   - Verify hints don't break remote query execution
   - Consider if Comdb2 should expose these hints to users

3. **Query Planner Testing**
   - Compare where.c join algorithm changes against Comdb2's planner
   - Test join order selection with distributed tables
   - Verify constant propagation doesn't break remote predicates
   - Benchmark query performance

4. **SELECT Processing**
   - Test compound SELECT with ORDER BY
   - Verify UNION/INTERSECT/EXCEPT still work correctly
   - Test with distributed queries across nodes

5. **Code Generator Review**
   - Review vdbe.c changes for performance optimizations
   - Ensure optimizations are compatible with Comdb2's VDBE modifications
   - Test code generation for complex queries
