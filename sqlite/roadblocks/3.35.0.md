# SQLite 3.35.0 Roadblocks

**Release Date:** 2021-03-12

## Changes
- Built-in SQL math functions (acos, asin, atan, atan2, ceil, cos, degrees, exp, floor, ln, log, log10, pi, pow, radians, sin, sqrt, tan, trunc)
- ALTER TABLE DROP COLUMN support
- Generalized UPSERT with multiple ON CONFLICT clauses
- RETURNING clause on DML statements (INSERT, UPDATE, DELETE)
- Improvements to bytecode generation and query planner

## Potential Roadblocks

| Change | Risk | Impact |
|--------|------|--------|
| Built-in math functions | Medium | New functions in **func.c** may conflict with Comdb2's custom function implementations. Need to verify no naming conflicts with existing Comdb2 functions. |
| ALTER TABLE DROP COLUMN | High | Requires parser changes in **parse.y** and schema modification code in **build.c**. May conflict with Comdb2's 80+ custom keywords and ALTER TABLE handling. |
| Generalized UPSERT (multiple ON CONFLICT) | Critical | Major changes to **insert.c** where Comdb2 has existing UPSERT modifications. Multiple ON CONFLICT clauses require parser and execution engine changes that likely conflict with Comdb2's insert logic. |
| RETURNING clause | Critical | Affects **insert.c**, **vdbe.c**, and **parse.y**. Requires new bytecode operations and result handling. High conflict probability with Comdb2's modified insert/update/delete handling. |
| Query planner improvements | Medium | Changes to **where.c**, **whereInt.h**, and related files. May affect Comdb2's query optimization customizations. |

## Action Items

1. **Math Functions Review**
   - Audit all math function names against Comdb2's custom functions
   - Test func.c integration with existing function registry
   - Verify no conflicts with Comdb2's function dispatch mechanism

2. **ALTER TABLE DROP COLUMN**
   - Review parse.y changes for grammar conflicts with Comdb2 keywords
   - Analyze build.c schema modification logic against Comdb2's schema change system
   - Consider whether to adopt SQLite's implementation or maintain separate path

3. **UPSERT Enhancement Critical Path**
   - Detailed diff of insert.c changes
   - Map SQLite's multiple ON CONFLICT logic to Comdb2's UPSERT implementation
   - Test suite for UPSERT behavior preservation
   - May require significant refactoring to merge both implementations

4. **RETURNING Clause Integration**
   - Parse grammar integration in parse.y
   - Bytecode changes in vdbe.c - verify compatibility with Comdb2's execution model
   - Result set handling in insert.c, update.c, delete.c
   - Test with Comdb2's distributed transaction model

5. **Query Planner Validation**
   - Regression test Comdb2's where.c customizations
   - Verify analyze.c statistics compatibility
   - Performance benchmarking of query plans

6. **Integration Testing**
   - Full regression suite against Comdb2 test cases
   - UPSERT compatibility tests
   - Schema change operation tests
   - Function compatibility tests
