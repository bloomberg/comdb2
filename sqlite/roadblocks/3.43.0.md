# SQLite 3.43.0 Roadblocks

**Release Date:** 2023-08-24

## Changes
- string_agg() aggregate function added
- group_concat() improvements
- Order-sensitive aggregate handling enhancements
- Aggregate function ORDER BY clause support improvements

## Potential Roadblocks
| Change | Risk | Impact |
|--------|------|--------|
| string_agg() aggregate function | Medium | New aggregate function requires parse.y integration, func.c modifications for aggregate registration. May conflict with Comdb2's custom aggregate handling. |
| group_concat() improvements | Medium | Changes to group_concat() implementation in func.c could conflict with any Comdb2 customizations to this function. |
| Order-sensitive aggregate handling | High | Modifications to aggregate processing in select.c, vdbe.c likely affect how aggregates with ORDER BY are compiled and executed. Could conflict with Comdb2's query execution model. |
| Aggregate ORDER BY support | High | Parser changes in parse.y for ORDER BY in aggregates, execution changes in vdbe.c and select.c. May conflict with Comdb2's aggregate window function handling. |

## Action Items
1. Review parse.y changes for aggregate function ORDER BY syntax additions
2. Check func.c for new aggregate function registrations (string_agg)
3. Analyze select.c and vdbe.c for order-sensitive aggregate execution changes
4. Test Comdb2's existing aggregate functions with ORDER BY clauses
5. Verify window function handling remains compatible
6. Review sqliteInt.h for new aggregate-related structures or flags
