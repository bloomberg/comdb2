# SQLite 3.34.0 Roadblocks

**Release Date:** 2020-12-01

## Changes
- Improvements to Common Table Expressions (CTEs)
- Added OP_SeekScan opcode for improved range queries
- Enhanced query planner for better index selection
- Support for UPDATE/DELETE on views with INSTEAD OF triggers
- Performance optimizations for large IN clauses
- Improved handling of correlated subqueries

## Potential Roadblocks

| Change | Risk | Impact |
|--------|------|--------|
| CTE improvements | **Medium** | Changes to **select.c**, **parse.y**. May affect Comdb2's handling of recursive CTEs and CTE optimization. Needs testing with distributed queries. |
| OP_SeekScan opcode | **High** | New opcode in **vdbe.c**, changes to **where.c**. Affects range query execution. Must verify compatibility with Comdb2's custom VDBE and remote execution. |
| Index selection enhancements | **Medium** | Modifications to **where.c**, **whereInt.h**. Could interact with Comdb2's index hints and custom query planning. |
| VIEW trigger improvements | **Low** | Changes to **trigger.c**, **build.c**. Should be compatible but test with Comdb2's trigger system. |
| IN clause optimization | **Medium** | Updates to **expr.c**, **where.c**. May affect query plans for large IN lists, test with Comdb2's expression handling. |
| Correlated subquery handling | **Medium** | Changes to **select.c**, **where.c**. Could impact remote subquery execution and optimization. |

## Action Items

1. **OP_SeekScan Integration** (High Priority)
   - Review new OP_SeekScan opcode implementation in vdbe.c
   - Understand where.c changes that generate this opcode
   - Test with Comdb2's btree and cursor implementations
   - Verify compatibility with remote query execution
   - Benchmark range query performance improvements

2. **CTE Testing**
   - Test CTE improvements with recursive queries
   - Verify non-recursive CTE optimization
   - Check interaction with MATERIALIZED hints from 3.32.0
   - Test CTEs in distributed query context

3. **Query Planner Review**
   - Compare index selection changes against Comdb2's planner
   - Test with Comdb2's index hints and covering indexes
   - Verify statistics usage (stat4) still works correctly
   - Benchmark complex queries with multiple index options

4. **IN Clause Optimization**
   - Test large IN clause performance
   - Verify optimization works with remote tables
   - Check memory usage for very large IN lists
   - Test with prepared statements and parameter binding

5. **Correlated Subquery Testing**
   - Test correlated subqueries in WHERE clauses
   - Verify proper execution with distributed tables
   - Check performance with nested correlations
   - Test with EXISTS and NOT EXISTS

6. **VDBE Compatibility**
   - Review all opcode changes
   - Test with Comdb2's VDBE modifications
   - Verify opcode serialization for remote execution
   - Run comprehensive VDBE test suite
